# Links Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Internal and web links in PDFs work: pointing hand and outline on
hover, a click follows, and an internal jump flashes the line at the target.

**Architecture:** The engine reads `/Link` annotations and resolves their
destinations (`Document::links`). A links thread in `noido-render`
(`Linker`, like `Thumbnailer`) answers a page's links and the flash area
of a target, using `noido-text` for the line. `noido-core` gets
`View::go_to_target`. The GUI keeps each page's links, hit-tests the
pointer, follows clicks, and draws the outline and the flash.

**Tech Stack:** Rust 2024, hayro 0.8 (hayro-syntax raw dictionaries),
eframe/egui 0.37, jj.

**Spec:** `docs/superpowers/specs/2026-10-26-links-design.md`

## Global Constraints

- Page points everywhere outside engine-hayro: origin top-left, y down,
  rotation applied: the space of `Glyph` and `page_size`.
- Malformed PDF input never panics; what can't be read is skipped.
- Web links open only for `http`, `https`, `mailto` (scheme compared
  case-insensitively); anything else does nothing.
- Zoom never changes on a jump.
- No new dependencies. Web links go through `egui::Context::open_url`.
- `cargo clippy --workspace --all-targets -- -D warnings` clean and
  `cargo fmt` after every task. TDD: each test watched failing first.
- Commits with `jj commit -m "<Area>: <what changed>"`; never move `main`.

## Review Focus

1. **Overlapping links:** where two link areas overlap, the last one in
   `/Annots` wins for hover and click. Test in Task 6.
2. **Pointer over a scroll bar or the sidebar** while over a link's
   position: no pointing hand, no follow. Test in Task 6.
3. **A link on a page whose links arrive after the pointer stopped:**
   the hand appears without moving the mouse. Test in Task 6.
4. **Reload while a flash runs or links are cached:** stale links and the
   flash are dropped; the new version's links are asked for. Test in
   Task 7.
5. **Destination page out of range / reference to a non-page object:**
   the link is dropped, not a panic or a jump to page 0. Test in Task 2.

### Task 4: The links thread

**Files:**
- Create: `crates/noido-render/src/links.rs`; export from `lib.rs`
- Test: in `links.rs` tests with a fake engine (as `thumbnails.rs` tests do), and `crates/noido-render/tests/` only if a fixture test reads better there

**Interfaces:**
- Consumes: `Document::links`, `Document::text`, `PageText::{new, line_near, text_span}`.
- Produces:
  ```rust
  pub enum LinkReply {
      Links { page: usize, links: Vec<Link> },
      /// `area`: the line, or a bar at the target's y, or None.
      Flash { target: Destination, area: Option<Rect> },
  }
  pub struct Linker { /* Sender<Command>, Receiver<LinkReply> */ }
  impl Linker {
      pub fn start(engine: Arc<dyn PdfEngine>, bytes: PdfBytes, waker: Box<dyn Fn() + Send>) -> Linker;
      pub fn request_links(&self, page: usize);
      pub fn request_flash(&self, target: Destination);
      pub fn try_recv(&self) -> Option<LinkReply>;
  }
  pub const FLASH_BAR_HEIGHT: f32 = 2.0;
  ```
- Behaviour: requests answered in order; `waker()` after each reply. A
  failed `links` call answers `Links` with no links. Flash: extract the
  target page's text, `line_near`; if `None` and `y` is given, a bar
  `Rect { x: left, y: y - 1.0, width: right - left, height: FLASH_BAR_HEIGHT }`
  where (left, right) is `text_span()` or, without text, 10 %…90 % of the
  page width; if `None` and no `y`, `area: None`. Text isn't kept.
  Document failing to open: thread ends, no replies.
