# The macOS app and click-to-open Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Clicking a PDF in Finder opens it in noido, one window per file,
each window in front; `noido --install` builds and registers
`~/Applications/noido.app`.

**Architecture:** `gui-egui/src/app_bundle.rs` holds everything pure (the
plist, the layout, the install plans, the Finder-launch decision, the
stale-app check) and compiles everywhere, so CI's Linux leg tests it. A new
crate `noido-macos` holds the AppKit calls (launcher mode, the open-URLs
handler, launching and activating windows) behind a handful of functions;
it is the only crate allowed `unsafe`. The GUI gets documents from a queue
it drains each frame, through the existing `open` hook.

**Tech Stack:** Rust 2024 (toolchain 1.99.1), eframe/egui 0.37, winit
0.30.13, objc2 0.6 / objc2-foundation 0.3 / objc2-app-kit 0.3 (already in
`Cargo.lock` through rfd), roxmltree 0.21, `codesign` and `lsregister`.

**Spec:** `docs/superpowers/specs/2026-10-31-macos-app-install-design.md`

## Global Constraints

- Bundle identifier `io.github.rikardg.noido`; bundle name `noido.app`;
  executable `Contents/MacOS/noido`, a regular file (a copy), never a link.
- `Info.plist`: `CFBundleExecutable=noido`, `CFBundleIdentifier`,
  `CFBundleName`/`CFBundleDisplayName=noido`,
  `CFBundleShortVersionString` = `env!("CARGO_PKG_VERSION")`,
  `CFBundlePackageType=APPL`, `LSMinimumSystemVersion=11.0` (Rust's
  aarch64-apple-darwin baseline), one `CFBundleDocumentTypes` entry
  (`LSItemContentTypes=[com.adobe.pdf]`, `CFBundleTypeName="PDF document"`,
  `CFBundleTypeRole=Viewer`, `LSHandlerRank=Alternate`), and
  `CFBundleURLTypes` with scheme `noido`. No icon, no `PkgInfo`, no
  `LSUIElement`, no `CFBundleTypeExtensions`.
- `lsregister` is
  `/System/Library/Frameworks/CoreServices.framework/Frameworks/LaunchServices.framework/Support/lsregister`.
- `unsafe_code` stays forbidden everywhere except `noido-macos`, which has
  `unsafe_code = "deny"` and a narrow `#[allow(unsafe_code)]` per call.
- noido never changes the default PDF app and never writes to
  `/Applications`.
- Hand tests: any bundle registered gets `lsregister -u` straight after;
  bundles live outside temp directories (`target/app/`); launch noido with
  a scratch `HOME` when its state must not be touched. No synthetic input.
- Commits: `jj commit -m "<prefix>: …"`; `egui` for `gui-egui`, `macos`
  for `noido-macos`, `Repo` for workspace setup. TDD: the failing test
  first, watched failing. `just check` clean before each commit.

## Review Focus

- A path with spaces, non-ASCII or `#` arriving from Finder: the GUI must
  open that exact file. Launcher and handler pass the URL's
  `absoluteString`, which `noido_core::parse_argument` already reads;
  Task 4 pins `file:` URLs with `%20` and `%C3%A9` through `opening`.
- `~/Applications/noido.app` that is not noido's (another identifier, or
  no readable plist): `--install` and `--uninstall` must leave it alone.
  Task 6 tests both plans.
- A running noido from an older build answering `ok` without a pid: the
  hand-over must still count as done. Task 5 tests the bare `ok`.
- `--app-bundle` into a directory that already holds a `noido.app`: it is
  replaced whole, with no stale files left in it. Task 1 tests it.
- A terminal `noido` with the app installed at the same version, or not
  installed, or someone else's: no hint. Task 7 tests all three.

### Task 3: Launcher mode (`noido-macos` crate)

**Files:**
- Create: `crates/noido-macos/Cargo.toml`, `crates/noido-macos/src/lib.rs`,
  `crates/noido-macos/src/launch.rs`
- Modify: root `Cargo.toml` (member, `noido-macos = { path = … }` and
  `objc2 = "0.6"`, `objc2-foundation = "0.3"`, `objc2-app-kit = "0.3"` in
  `[workspace.dependencies]`)
- Modify: `crates/frontends/gui-egui/Cargo.toml`
  (`[target.'cfg(target_os = "macos")'.dependencies] noido-macos.workspace = true`)
- Modify: `crates/frontends/gui-egui/src/main.rs`

**Interfaces:**
- Produces in `noido-macos` (every item `#[cfg(target_os = "macos")]`; the
  crate is empty elsewhere; objc2 dependencies under a macOS target table):
  - `pub fn launch_in_bundle(app: &Path, args: &[OsString], done: impl FnOnce(Result<(), String>) + Send + 'static)`:
    `NSWorkspace::openApplicationAtURL_configuration_completionHandler`
    with `arguments = args`, `createsNewApplicationInstance = true`,
    `activates = true`; `done` runs from the completion handler.
  - `pub fn run_launcher(app: &Path) -> !`: a bare `NSApplication` (no
    winit) whose delegate (`define_class!`) collects
    `application:openURLs:`'s `absoluteString`s; at
    `applicationDidFinishLaunching:` exits 0 at once when none came,
    otherwise calls `launch_in_bundle(app, &[url])` for each URL in order
    and exits 0 when every `done` has run, or after 5 s whichever is first.
- Produces in `main.rs`:
  - `fn without_psn(args: impl IntoIterator<Item = OsString>) -> Vec<OsString>`:
    drops arguments starting with `-psn_`.
  - `fn is_finder_launch(args: &[OsString], exe: &Path) -> bool`: true
    when `args` is just the program name and `app_bundle::bundle_of(exe)`
    is `Some`.
  - `main` reads `without_psn(std::env::args_os())`; on macOS, when
    `is_finder_launch(&args, &current_exe)` (current_exe **not**
    canonicalized), calls `noido_macos::run_launcher(&bundle)`; otherwise
    `Args::parse_from(args)`.

Decision: the launcher passes each URL as text, `file:` URLs included;
`noido_core::parse_argument` already reads `file:` and `noido:` links,
so there is no URL-to-path code in the launcher.

### Task 4: Later opens reach the running noido

### Task 6: `noido --install` / `--uninstall` on macOS
