# Search UI — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Live search from the title bar's field: every match highlighted on the pages, a results list in the sidebar, and next/previous from the keyboard, built on part 1's `TextSearcher`.

**Architecture:** `noido-core` gets the pure parts: `KeyPress.shift` with bindings for next/previous hit, a `Hits` store that keeps hits in document order while they arrive out of order and answers "next from here", and `View::reveal` that brings a hit's rectangles into view. The frontend gets a `search.rs` module owning the searcher, the debounce, the generation and the "jump once" state; `app.rs` wires it to the field, the keys, the reload path and the page drawing; the sidebar shows a results list (`results.rs`) instead of thumbnails while the field has text.

**Tech Stack:** Rust 2024, eframe/egui 0.37; `noido-text` and `noido-render::TextSearcher` from part 1.

**Spec:** `docs/superpowers/specs/2026-10-25-search-ui-design.md` (part 2; part 1 is `2026-10-25-text-layer-design.md`)

## Global Constraints

- `unsafe_code = "forbid"`; clippy clean: `cargo clippy --workspace --all-targets -- -D warnings`.
- Debounce: a search starts `0.2` s (egui input time) after the last change to the field. No minimum length.
- `TextSearcher::extract()` is called the first time the field gets focus, never at open.
- Each query searches from the current page (`current_page()`); hits arrive page by page, possibly out of order; the store keeps document order (page, then position in the page text).
- The view jumps once per query, to the first hit received, unless the reader moved the page view since the query started. Hits arriving later never move the view.
- "The reader moved" is exactly what clears `chosen` today (`reader_moved()`), plus a thumbnail click.
- Next/previous: from the current hit if the view is still where the last hit put it; else from the view: next = first hit starting at or below the view's top edge, previous = last hit starting above its bottom edge. Both wrap. No hits: nothing.
- Keys: Enter / Shift+Enter in the field; Mod+G / Mod+Shift+G and F3 / Shift+F3 everywhere.
- Esc in the field with text: clears query, hits and highlights, the sidebar shows thumbnails, focus stays. Esc with an empty field: today's behaviour.
- A search opens the sidebar only when the field goes from empty to non-empty and the sidebar is closed; that counts as opened by search.
- Going to a hit keeps zoom and modes; a hit fully visible doesn't move the view; otherwise its rectangles' union is centred.
- Results list in document order; only visible rows drawn; current row marked with the selection colour and kept in view.
- Counter "3 of 41", "41 matches" with no current hit, "5000+" when cut short, "No matches" when done with none.
- Never send synthetic input to the desktop; smoke tests only launch, screenshot and signal.

## Review Focus

1. **Reader scrolls while the first hit is still on its way** (big book, rare word): the view must stay. Test: `reader_move_cancels_pending_jump` (Task 5).
2. **Hits arriving after wrap-around** (pages before the current one come last) must not change which hit is current, only its number. Test: `insert_before_current_keeps_current` (Task 2).
3. **Updates from an older query** still in the channel after typing more: ignored. Test: `stale_generation_is_ignored` (Task 5).
4. **Next/previous with no hits, or before any arrive:** nothing happens, no panic. Test: `next_without_hits_does_nothing` (Task 6).
5. **Paged mode, hit on another spread:** next shows that spread and the hit. Test: `next_in_paged_mode_flips_to_hit` (Task 6).

### Task 5: Live search, results in, jump once, Esc, sidebar

**Files:**
- Modify: `search.rs`, `app.rs`, `titlebar.rs`

**Interfaces:**
- Consumes: `Hits` (Task 2), `View::reveal` (Task 3), `Search` (Task 4).
- Produces: per frame, before drawing: if the field's text differs from `searched` and `changed_at` is 0.2 s ago, send `search(text, current_page)`, clear hits, `first = Jump`, reset progress; while waiting, `request_repaint_after` the rest of the delay. Take in updates of the current generation only: `add_page`, count pages; on the first non-empty page with `first == Jump`: set current to that page's first hit and `View::reveal` it, `at_hit = true`, `first = Done`; with `first == Select`: set current without moving. `reader_moved()` sets `first = Done` if it was `Jump`, and clears `at_hit`. Empty field: `search("")`, clear everything. Reload with text: new search with `first = Select`, no jump.
- Titlebar `Output`: `cancelled` stays (Esc lost focus); app: Esc with non-empty `search` → clear the text and the search, request focus back, sidebar unchanged; with empty text → today's behaviour. Enter no longer opens the sidebar (it steps in Task 6). The field going from empty to non-empty opens a closed sidebar and sets `sidebar_opened_by_search`.

### Task 7: Drawing — highlights, results list, counter

**Files:**
- Create: `crates/frontends/gui-egui/src/results.rs`
- Modify: `sidebar.rs` (`Input.results: Option<results::Input>`; `Output.hit: Option<usize>`), `app.rs` (`pages()` draws highlights), `titlebar.rs` (`Bar.counter: Option<String>` drawn just right of the field)

**Interfaces:**
- `results::Input<'a> { hits: &'a Hits, status: Status }` with `enum Status { Searching { searched: usize, of: usize }, Done { cut_short: bool } }`. `results::show(ui, input, follow: Option<usize>) -> Option<usize>` (clicked hit). Rows of fixed height through `ScrollArea::show_rows`; each row: "p. N" in weak text, then the context in one line, the bold range in the strong text colour on a faint highlight fill (egui's default fonts have no bold: my call), elided at the row's end. The current row filled with `selection.bg_fill`. When the current hit changes, the list scrolls the least distance to show its row. Above the rows: "Searching… page N of M" while searching; "No matches" when done with none.
- While results show, the sidebar's thumbnails count as closed for sharp renders (`SidebarView::closed()`).
- Highlights in `pages()`: for each visible page, each hit's rects mapped to screen (`content.min + page_rect.min + rect × layout.scale()`), filled with `HIGHLIGHT_FILL` (yellow, alpha ~90); the current hit with `CURRENT_FILL` (orange, alpha ~140). Constants in `app.rs` or `search.rs`.
- Counter text (`search.rs`, unit-tested): `"3 of 41"`, `"41 matches"` (no current), `"3 of 5000+"`, `"No matches"` (done, none), `""` (no query).
