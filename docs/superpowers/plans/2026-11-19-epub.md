# EPUB as typeset pages (E1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An `.epub` opens in noido as typeset pages in the house
style, with locations, links and outline working as for markdown.

**Architecture:** `noido-blocks` gains an XHTML producer beside
markdown. A new crate `noido-epub` reads the container, package, spine
and table of contents into parts. `noido-typeset` sets a book part by
part (markdown is a book of one part) and its engine accepts EPUB
bytes; `gui-egui` routes EPUB ZIPs to it instead of the comic engine.

**Tech Stack:** Rust 2024; roxmltree 0.21, zip 9, percent-encoding 2.3
(all already workspace dependencies); Python 3 for fixtures.

**Spec:** `docs/superpowers/specs/2026-11-19-epub-design.md`

## Global Constraints

- TDD: every behaviour's test is written first and watched failing.
- Commits with `jj commit -m`, one per task unless a task says more;
  prefixes by crate: `blocks`, `epub`, `typeset`, `engine`, `egui`,
  `Repo`. Titles ≤ 72 characters. Never move the `main` bookmark.
- `just check` (tests, clippy clean, fmt) passes at the end of every
  task, in repo-2.
- Tests use only `fixtures/` and inline strings, never `../testfiles/`.
- No new external dependencies.
- A part is a spine item; its number is its place in the spine.
  `linear="no"` is ignored. Parts are set in spine order.
- A part's characters: the text of every text node under `<body>`, in
  document order, after entity decoding and NFC, whitespace included,
  except inside `<script>` and `<style>`. Tree spans are offsets into
  that.
- Size limit: the spine's XHTML, uncompressed, at most `MAX_SOURCE`
  (8 MB); the message is the existing one: `too large to typeset (N MB;
  the limit is 8 MB)`.
- Error copy (as `EngineError::Open`), exactly:
  `not a readable EPUB: not a ZIP archive`,
  `not a readable EPUB: no container`,
  `not a readable EPUB: no package`,
  `not a readable EPUB: the spine is empty`,
  `this EPUB is DRM-protected`.
- An unreadable spine item is set as one paragraph:
  `This chapter could not be read.`
- The image stand-in: alt text in italic; `[image]` in italic when the
  alt is empty or equals the `src` file stem (ignoring case).

## Review Focus

1. A chapter file starting with a UTF-8 BOM, or not UTF-8 at all: the
   BOM is skipped; non-UTF-8 makes that part unreadable, the book still
   opens. (Task 2.)
2. A link to an id on an empty element (`<a id="x"/>` just before text,
   as non-fiction endnotes do): it lands on the text that follows; an id
   at the very end of a part lands at the part's end. (Tasks 3, 7.)
3. A spine `idref` missing from the manifest: that part is unreadable,
   the book opens and later parts keep their numbers. (Task 4.)
4. Whitespace-only text between blocks (indentation in the XHTML) makes
   no empty paragraphs, and counts toward the part's characters.
   (Task 2.)
5. A link to something not in the spine (an image, a CSS file, a file
   that doesn't exist): kept as styled text, not clickable, no panic.
   (Task 7.)

## Fixtures (used from Task 4 on)

Generated by `fixtures/make_fixtures.py` (Task 4 adds the functions and
`__main__` lines). Every EPUB has `mimetype` as its first entry, stored,
reading `application/epub+zip`, and `META-INF/container.xml` naming the
package. Chapter files are XHTML with `xmlns="http://www.w3.org/1999/xhtml"`
and `xmlns:epub="http://www.idpf.org/2007/ops"`.

**`book.epub`** (EPUB 3, package `OEBPS/content.opf`):
- metadata: title `A Small Book`; creators `Ann Author`, `Bo Writer`;
  language `sv`; subject `Tests`.
- manifest: `cover.xhtml`, `cover.png` (`properties="cover-image"`, a
  1×1 PNG), `nav.xhtml` (`properties="nav"`), `text/ch1.xhtml`,
  `text/ch 2.xhtml` (href written `text/ch%202.xhtml`).
- spine: cover, ch1, ch 2 (nav not in the spine).
- `cover.xhtml`: `<body><section epub:type="cover"><img src="cover.png" alt="Cover"/></section></body>`.
- `text/ch1.xhtml` body:
  `<h1>Chapter One</h1><p>It was a <i>dark</i> and <b>stormy</b> night.</p><p>See <a href="ch%202.xhtml#later">later</a>, and H<sub>2</sub>O<sup>1</sup>.</p><hr/><ul><li>first</li><li>second</li></ul><table><tr><th>A</th><th>B</th></tr><tr><td>1</td><td>2</td></tr></table><pre>  two  spaces</pre><p><img src="../images/f0001-01.png" alt="f0001-01"/></p>`
- `text/ch 2.xhtml` body:
  `<h1 id="top">Chapter Two</h1><p id="later">Later text.</p><p>Back to <a href="ch1.xhtml">the start</a>, <a href="https://example.com/">the web</a> and <a href="../cover.png">a picture</a>.</p>`
- `nav.xhtml`: `<nav epub:type="toc"><ol><li><a href="text/ch1.xhtml">Chapter One</a></li><li><a href="text/ch%202.xhtml#top">Chapter Two</a><ol><li><a href="text/ch%202.xhtml#later">Later</a></li></ol></li><li><a href="nowhere.xhtml">Missing</a></li></ol></nav>`

**`book2.epub`** (EPUB 2, package `content.opf` at the root, NCX):
- metadata: title `Second Book`, one creator `Cy Penn`, no language.
- spine (`toc="ncx"`): `one.html`, `notes.html` (`linear="no"`), an
  itemref whose idref is not in the manifest, `broken.html`, `two.html`.
- `one.html`: starts with a UTF-8 BOM; body
  `<p>Hello&nbsp;world.</p>\n  \n<p>Note<a id="r1"/><sup><a href="notes.html#n1">1</a></sup> here.</p><a id="end"/>`
- `notes.html`: body `<p id="n1">The note. <a href="one.html#end">Back</a></p>`
- `broken.html`: `<html><body><p>unclosed</body></html>`
- `two.html`: encoded as Latin-1 (not UTF-8): body `<p>Caf\xe9</p>`.
- NCX: navPoints `One` → `one.html`, `Notes` → `notes.html#n1`, with
  `Notes` nested under `One`.

**`drm.epub`**: like a one-chapter `book2.epub`, plus
`META-INF/encryption.xml` with an `EncryptedData` whose
`CipherReference URI` is the chapter's path.

**`obfuscated.epub`**: the same, but `encryption.xml` names only
`fonts/f.otf` (a manifest item with media type `font/otf`, a few
arbitrary bytes). It opens.

**`not-epub.zip`** isn't needed: `comic.cbz` stands for any ZIP that
isn't an EPUB.
