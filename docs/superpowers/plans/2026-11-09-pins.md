# Pins Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a Pins tab beside Pages, a pin control on Pages thumbnails, and a floating "pagelet" that previews a pinned page with live links.

**Architecture:** `Pins` is a sorted list of page numbers in `noido-core`, saved with the rest of the document's state in `noido-state`. The sidebar keeps its one renderer and sharp-image map; the Pins tab lays out only the pinned pages in a `Column`, keeps them as `Keep::extra` alongside the Pages window, and draws the same card. The pagelet is an `egui::Window` over the pages, its page fitted by a pure helper in `noido-core`, drawn from the main renderer's `textures` (the previewed page joins the main renderer's `extra` keep at the panel's scale), with link hits mapped back to page points through the fit.

**Tech Stack:** Rust 2024, egui 0.37 (eframe), jj, cargo/nextest. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-09-pins-design.md`

## Global Constraints

- jj, not git: commit with `jj commit -m "<message>"`; never move the `main` bookmark. Never `git add`/`commit`/`stash`.
- Commit title ≤ 72 characters, prefix is the crate where the point is: `core`, `state`, `egui`. A review fix is a `fixup: <crate>: …` commit, squashed into the commit it corrects.
- TDD, always: write the failing test, run it and watch it fail, then implement, then run it green.
- `just lint` (clippy) must be clean; `just fmt`; `just test` (nextest if installed).
- `gui-egui` is a binary crate: `cargo test -p gui-egui <name>` (no `--lib`).
- The sidebar's `SIDEBAR_MIN_WIDTH` stays 160; tab labels truncate; four labels must all fit their tabs at 160.
- Pins are ordered by page, unique, pruned to the page count.
- No glow on the Pins tab, and no highlights, selection or text in the pagelet: they are out of this change.
- Never send synthetic input to the desktop; drive behaviour through `Harness` in `app.rs`.
- Any manual run uses a scratch `XDG_STATE_HOME`; stop the app with `pgrep -x noido | xargs -r kill -INT`.

## Review Focus

1. **A pin past the end after a reload.** A document reloaded to fewer pages must prune its pins and close a pagelet showing a page that is gone, without a panic on `page_sizes[index]`. Test: task 6.
2. **The previewed page also on screen at another scale.** Zooming out with a page both visible and previewed must settle on one requested scale (the larger), not re-request each frame. Test: task 7.
3. **A click inside the pagelet.** It must not reach the page underneath the panel: not a link under it, not a pan, and at most one history entry. Test: task 9.
4. **The pin and the card it sits on.** Both share the top-right corner of a thumbnail; a click on one must not do the other's job. Tests: task 3 (a card click pins nothing) and task 6 (a pin click opens no pagelet).
5. **The fade settling.** Mid-fade and under reduced motion the pagelet must not repaint forever or get stuck translucent. Test: task 8.

/// Where page point (`x`, `y`) of the pagelet's page is on screen.
fn pagelet_pos(h: &Harness, x: f32, y: f32) -> egui::Pos2 {
    let page = h.app.view.layout().page_size(h.app.pin_preview.as_ref().unwrap().page).unwrap();
    let fitted = h.app.pagelet_page_rect().unwrap();
    let s = fitted.width() / page.width;
    fitted.min + vec2(x * s, y * s)
}
